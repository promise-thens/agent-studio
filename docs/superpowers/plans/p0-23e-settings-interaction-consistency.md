# 设置页面与交互一致性实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**目标：** 统一设置页的信息层级、窄窗口适配、保存反馈和键盘操作。

**核心数据流：** 设置壳管理导航、焦点和离开确认，各子页继续调用原有业务 API；保存成功、失败和未保存状态汇报给壳层，不改变密钥与 Runtime 配置所有权。

**约束与边界：** 对应问题 2.6、2.7 的设置部分。统一供应商、外观、记忆、Grok 配置、浏览器、Hooks 页面；不新增 Provider 框架，不修改设置的实际功能或保存协议。

**主要风险：** 固定双栏挤压表单；多重滚动使操作区不可见；离开丢草稿；焦点跑到背景网页；保存失败却显示成功。

**技术栈：** Vue 3、现有 CSS 变量、TypeScript、Vitest、Electron 开发版。

**状态：** 已核查设置壳结构，未执行 GUI；计划待批准。

## 任务 1：统一设置壳

**文件：** `SettingsDialog.vue`、`settings-dialog.ts`、`assets/main.css`、`settings-dialog.test.ts` 及相关样式。

- [ ] 保留现有导航分类，用一致页标题、说明、内容区和操作区；窄窗口导航降级为紧凑选择器。
- [ ] 明确单一内容滚动责任，固定操作区不能遮挡最后一个字段，长内容仍可访问。
- [ ] 打开时聚焦合理入口，Tab/Shift+Tab 圈定焦点，Esc 按未保存规则退出，关闭后回到触发按钮。
- [ ] 弹窗存在时协调原生浏览器可见性，不能让背景 WebContentsView 拦截点击或键盘。
- [ ] 验证窗口高度不足、文本缩放、键盘导航、关闭再打开及浏览器同时打开。

**完成标志：** 所有设置页共享可预测的导航与操作区域，键盘焦点不逃出模态。

## 任务 2：六类页面的布局与反馈

**文件：** `src/renderer/src/components/` 中六类设置页面及对应展示函数/测试，复用现有 `base.css`、`button.css`、`menu.css`。

- [ ] 供应商：表单字段、错误关联、测试/保存/重试布局一致，已保存 Key 仍只显示状态；HTTP 提示和 origin 变更重新输入 Key 规则保留。
- [ ] 外观：选项即时生效反馈统一，不为即时保存项伪造未保存按钮。
- [ ] 记忆：列表与正文按容器宽度折叠，编辑草稿在切页或关闭前确认；保留错误与保存结果。
- [ ] Grok 配置：编辑区优先，说明栏窄时折叠；配置解析错误定位可见，不吞掉原始草稿。
- [ ] 浏览器：开关按用途分组，当前操作状态与持久化结果分开；不改变出厂行为、Cookie 或登录态策略。
- [ ] Hooks：明确只读库存，不把查看按钮设计为执行按钮，空态与扫描失败分开。
- [ ] 子页需要离开确认的统一汇报 dirty/saving/error；保存失败不清 dirty，明确丢弃才关闭。

**完成标志：** 六类页面视觉与操作一致，各自语义保持真实，不改底层配置协议。
