# P0-06 任务与会话历史 实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**优先级：** P0 / 权重 4（可恢复任务闭环）

**目标：** 保存可恢复的本地任务索引、状态摘要和脱敏事件，兼容 Runtime 自己的会话标识而不替代其历史。

**核心数据流：** 统一服务为每次任务创建本地 taskId 并关联 runtimeSessionId；归一化事件写入有界本地记录；恢复时先读取摘要，再由 Adapter 尝试恢复原会话。

**约束与边界：** 不持久化 API Key、完整屏幕内容、剪贴板、未脱敏命令环境或无上限推理；不声称所有 Runtime 都支持原生恢复。

**主要风险：** 记录损坏或 Runtime 已删除会话；版本化 schema、原子写入、可读只读历史和明确“无法继续但可查看”状态。

**技术栈：** Electron 39、Vue 3、TypeScript、electron-vite、pnpm 10、Node.js 20+、Vitest；需要 Runtime 协议时以当期官方 schema 与本机实测为准。

## 实施范围

**前置依赖：**
- 依赖 P0-01、P0-02、P0-05。

**文件范围：**
- 新增 `src/main/agent/task-history-store.ts`、测试；`src/shared/agent.ts`；`src/renderer/src/composables/useTaskHistory.ts`。

**安全策略：**
- 安全是与操作风险匹配的护栏：低风险只读操作可在任务范围授权；写入与命令需展示目标和影响；删除、外发数据、登录态、屏幕和剪贴板始终显式确认。
- Renderer 不接触密钥、任意 IPC、文件系统或子进程；所有跨进程数据须可序列化、限长并脱敏。
