# 对话展示与输入控件实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**目标：** 文件变更留在所属轮次，Token 用圆环呈现，统一输入菜单与对话阅读层级。

**核心数据流：** 现有 Timeline、上下文 Usage 与轮次检查点经过展示函数，输出对话及 Composer 模型；文件详情仍向现有 Changes 服务查询，不复制 Diff 事实。

**约束与边界：** 对应问题 1.7、2.1、2.2、2.3，以及 2.7 的对话部分。复用 `base.css` 颜色/字体/圆角及已有 Phosphor 图标；保留深浅主题和键盘操作，不添加营销页装饰或另一套 UI 框架。

**主要风险：** Task 当前 Diff 冒充历史轮 Diff；未知用量显示成零；菜单被聊天容器裁剪；弱化视觉时丢失失败、停止或权限反馈。

**技术栈：** Vue 3、CSS 变量与容器响应布局、TypeScript、Vitest。

**状态：** 截图及代码已核查，计划待批准，未实现。

## 任务 1：变更卡轮次归属

**文件：** `TaskConversation.vue`、`TaskChangeCard.vue`、`task-changes-presentation.ts`、`composables/useTaskChanges.ts`、相关样式及测试。

**证据：** 当前卡片明确挂到最后一轮，数据却是 Task 级当前 ChangeSet，新轮开始会把旧变更带到末尾。

- [ ] 从现有 `listTurnCheckpoints` 获取轮次及路径归属，使用稳定 turnId 渲染历史摘要；不能用数组最后一项推断归属。
- [ ] 历史摘要只展示可证实的路径和状态；当前相对 HEAD 的行数、Diff 不标作历史轮增量。
- [ ] 当前工作区详情以“查看当前变更”明确标识；没有检查点的旧数据不伪造轮次归属。
- [ ] 摘要默认紧凑折叠、降低底色和按钮权重，与对话正文一起滚动；保留必要审阅和恢复入口。
- [ ] 测试第一轮改文件、第二轮不改、第三轮再改、历史分页、外部漂移、无 Git 项目和切 Task。

**完成标志：** 后续对话不会搬走旧轮摘要，未改文件的轮次不继承旧卡；审阅事实不失真。

- [ ] 复用现有 `usage(scope=context)` 最近可信样本，不另建 token 采集器。

- [ ] 删除首轮强制将真实样本清零的展示逻辑；上下文占用不解释成累计计费 Token。
- [ ] 悬停和键盘聚焦均可查看详细 used、limit、百分比、来源或更新时间；支持 Esc 关闭，无数据时说明未提供。

**完成标志：** 常态只占小圆环空间，详情按需出现，数字与真实事件一致。
