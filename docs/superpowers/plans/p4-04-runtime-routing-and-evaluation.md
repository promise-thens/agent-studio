# P4-04 Runtime 路由与评估 实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**优先级：** P4 / 权重 2（最后的优化能力）

**目标：** 基于用户可见的任务特征、能力、成本、速度和历史结果推荐 Runtime/Profile 组合，并在获得明确授权后才允许自动路由。

**核心数据流：** 任务创建时生成最小特征摘要；本地评估器读取脱敏历史聚合指标和可用组合；UI 显示推荐理由、预计成本/限制，用户选择或授权执行。

**约束与边界：** 默认只推荐、不自动花费或执行；不上传任务内容用于训练；不以少量样本给出确定性质量结论；用户可关闭历史参与。

**主要风险：** 历史数据偏差、费用预测错误和黑箱决策；展示样本量、条件、置信度、成本上限和用户覆盖入口。

**技术栈：** Electron 39、Vue 3、TypeScript、electron-vite、pnpm 10、Node.js 20+、Vitest；需要 Runtime 协议时以当期官方 schema 与本机实测为准。

## 实施范围

**前置依赖：**
- 依赖 P4-02、P4-03 与足够的本地历史数据。

**文件范围：**
- 新增 `src/main/agent/routing-evaluator.ts`、测试；新增 `RoutingRecommendation.vue`；修改任务启动与本地审计。

**安全策略：**
- 安全是与操作风险匹配的护栏：低风险只读操作可在任务范围授权；写入与命令需展示目标和影响；删除、外发数据、登录态、屏幕和剪贴板始终显式确认。
- Renderer 不接触密钥、任意 IPC、文件系统或子进程；所有跨进程数据须可序列化、限长并脱敏。
