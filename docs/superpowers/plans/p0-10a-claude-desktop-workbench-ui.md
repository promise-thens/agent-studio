# P0-10A Claude Desktop 风格工作台大修

> **致执行者：** 产品已确认当前界面太重、太碎，要按 **Claude Code Desktop** 的便捷度大修：对话是唯一主角，工具和子 Agent 收进安静的嵌套行，不要再做三栏卡片仪表盘。
>
> **状态：** 助手正文 Markdown 已接入主列；Task 2 对话块/计划清单/工具行/流内权限已落地。子 Agent 无父子字段保持扁平（前置：P0-09 测试门关闭，时间线数据模型稳住）
>
> **插入点：** P0-09 之后、P0-10 状态拆分之前或与之同迭代。**P0-10 必须消费本计划的视觉语言，禁止再发明第三套皮肤。**
>
> **产品来源：** 2026-08-18 用户确认整站按 Claude Code Desktop 大修；随后明确 **对话、计划、子 Agent 三件都要做成 Desktop 那种**，不是只改壳。子 Agent 协议分组见 [GACP-06](grokACP计划/gacp-06-subagent-timeline.md)。

**优先级：** P0-A / 权重 5（没有像样的对话界面，后面的恢复、权限、Git 都没有落点）

**目标：** 用户打开应用后的第一感觉是「一个干净的对话」，不是「一个堆满芯片和面板的控制台」。

具体要做到：

1. 去掉三栏圆角投影卡片；改成侧栏 + 主对话，检查器变成按需抽屉。
2. 主列是一条连续对话流，不是 `TurnSummaryCard` 里 `Tool · in_progress` 这种调试输出。
3. 输入框沉在底部，模型切换、发送、停止都在输入框里，不要页眉一排「连接 Grok」。
4. 点进历史就能打字（GACP-02），不要「只读历史 + 继续任务」横幅。
5. **对话 / 计划 / 子 Agent** 都在主列一条流里，做成 Claude Code Desktop 那套，不要拆到右侧检查器当调试面板。

**核心数据流：** 不改 IPC / Task / 权限事实。本计划只改 Renderer 的信息架构和 CSS。P0-09 的 timeline model 继续当唯一数据源。

**约束与边界：**

- 学的是 **布局、密度、便捷**，不是抄 Claude 商标、字标、专有插画或私有组件。
- 继续深色桌面工作台，优先复用并收敛现有 CSS 变量，不要引入第二套颜色体系。
- 不在本计划实现 P0-12 Diff 引擎、P0-15 终端、P3 Computer Use。这些在检查器抽屉里用安静占位。
- Titlebar 交互控件保持 `-webkit-app-region: no-drag`；图标按钮要有 `title` / `aria-label`；保留 `prefers-reduced-motion`。
- 小窗口优先藏次要信息，必须保住：对话流、输入框、发送/停止、模型选择。

**主要风险：**

- 只换圆角不改信息架构，看起来还是控制台。
- 和 P0-10 抢着拆 `App.vue`，两套组件。本计划先定壳和视觉，P0-10 把状态搬进这些壳。
- 把工具信息藏太深，审批和失败看不见。进行中的工具/子 Agent/权限必须在折叠态也看得出状态。

**技术栈：** Vue 3、现有 Phosphor 图标、现有 CSS 变量、Vitest + Vue Test Utils。不新增 UI 框架。助手 Markdown 用自研 AST + Vue 节点渲染，不引入 markdown 库，不使用 `v-html`。

## 现在为什么难看（对照代码）

这些是大修对象，不是细枝末节：

| 现状 | 文件 | 问题 |
| --- | --- | --- |
| 左 272 + 中 + 右 310 三块 22px 描边投影卡片 | `main.css` `.workspace-layout` | 像仪表盘，对话被夹在中间 |
| 页眉 66px：项目名 + 状态芯片 + 连接/断开 | `.chat-header` | 每次进对话先看到运维按钮 |
| 「只读历史」整条横幅 + 继续任务 | `App.vue` | 和 GACP-02 冲突，也打断阅读 |
| 左侧轮次锚点轨 | `.turn-anchor-rail` | 调试感，Claude Desktop 没有 |
| 时间线把节点打成 `Tool` / `Plan` / `Permission` 标签 | `TurnSummaryCard.vue` | 像日志查看器 |
| 每次 `plan` 事件再插一张「Plan · N 项」 | `task-timeline-reducer.ts` | Desktop 是原地打勾的一张清单 |
| 计划被放进右侧「执行计划」栏 | `App.vue` inspector | 计划和对话拆开了，不像 Desktop |
| 检查器常驻 310px | `.inspector-panel` | 主列永远窄 |
| `App.vue` 又管连接又管历史又管样式 | `App.vue` | 换皮会和业务缠死 |

Claude Code Desktop 相反：

- 侧栏很窄，几乎只有对话列表和新对话。
- 中间是一条好读的字，工具是一行行收起的记录。
- 子任务是嵌在流里的小卡片，点开才展开。
- 输入框是整页最稳的控件；停止就在输入框旁。
- 连接、项目、设置不挡在对话前面。

## 已锁定的视觉语言

### 1. 布局

```text
┌ titlebar（薄，品牌靠左，设置靠右）─────────────┐
│ ┌ 侧栏 220 ┐┌ 主对话 ─────────────────────────┐ │
│ │ 新对话    ││ 对话标题（一行，可内联改）        │ │
│ │ 项目 ▾    ││                                 │ │
│ │ 对话列表  ││  用户这句话                      │ │
│ │           ││  思考（折叠）                    │ │
│ │           ││  读了 8 个文件          ▸        │ │
│ │           ││  ┌ 子 Agent 探查测试  running ┐ │ │
│ │           ││  │  3 个工具 · 点开看         │ │ │
│ │           ││  └───────────────────────────┘ │ │
│ │           ││  正式回复                       │ │
│ │           ││                                 │ │
│ │           ││ ┌ 输入框  模型 ▾      发送/停 ┐ │ │
│ │           ││ └─────────────────────────────┘ │ │
│ └───────────┘└─────────────────────────────────┘ │
└──────────────────────────────────────────────────┘
```

检查器默认关上，从标题栏一个按钮滑出，盖在右侧，不挤对话列。

禁止再使用：

- 三栏同时是「大圆角卡片 + 重阴影」
- 主列顶部主按钮「连接 Grok」
- 只读历史横幅
- 轮次圆点锚点轨作为默认导航

连接是环境问题：未配置 Provider 仍走引导页；已配置时点对话即按 GACP-02 后台接上。页眉最多一行弱状态，例如「正在接回上下文…」。

### 2. 密度和字体

- 对话正文 14–15px，行高 1.55，最大阅读宽约 760px，居中。
- 工具行、时间、状态 12px，颜色用 `--text-3`。
- 侧栏 13px。
- 垂直节奏靠空白，不靠每条消息一套描边卡片。
- 用户消息可以轻底；助手消息无气泡，直接是字。

### 3. 颜色

继续用 `base.css` 的 token，做减法：

- `--app-bg` / `--surface-1` 几乎连成一块，侧栏只用 1px 分割，不要各包一层阴影。
- `--accent` 只给发送、当前对话高亮、进行中指示。
- 成功/危险只出现在真的终态和审批，不要每条 tool 一颗彩点。
- 浅色主题可以切换。

### 4. 输入框（整页最重要的控件）

一个圆角容器，贴主列底：

- 多行输入，Enter 发送，Shift+Enter 换行（已有输入法保护要保留）。
- 左下：模型选择（现成 `ModelSelector`），执行中禁用。
- 右下：空闲是发送，执行中是停止。停止必须始终能看见。
- 可选一行极小字：上下文 used/limit，没有数据就藏起来。
- 不要在输入框上方再做一排快捷键说明书；小窗更不要。

### 5. 侧栏

- 顶：新对话（主操作）。
- 项目切换收成一个小下拉或一行，不要大卡片堆路径。
- 下面就是对话标题列表，当前项一条浅底。
- 运行中的对话左侧一条细 accent，不要大状态芯片。
- 删除、设置进右键或 `⋯`，不要每行四个图标。

### 5A. 对话、计划、子 Agent（必须像 Claude Code Desktop）

这三件是同一条流上的三种块，不是三个面板。用户点进一条 Task，只该看见：

```text
你：把登录改成支持邮箱

思考过程                          ▸   ← 默认折
计划                              ▸
  ☐ 找现有 auth
  ◐ 改登录表单                      ← 当前这一步
  ☐ 补测试

▸ 读了 src/auth.ts
┌ 探查测试结构              进行中 ▾ ┐
│  3 个工具                          │
└────────────────────────────────────┘

登录表单已经改成邮箱，测试还没跑完。
```

检查器里那块「执行计划」「工具活动」**不再作为主界面**。计划必须离开右侧栏，进对话流。

#### 对话

对标 Desktop 的阅读体验，不是聊天气泡墙。

| 块 | 怎么画 |
| --- | --- |
| 用户 | 轻底或靠右一小段，字 14–15px，不要大描边气泡 |
| 助手正式回复 | 无气泡，Markdown 可读（标题、列表、行内强调、围栏代码、GFM 表格、http/https 外链） |
| 思考 | 一行「思考过程」，默认折；展开是灰字，不和回复抢权重 |
| 流式 | 同一个 message 节点往后长，不要每个 chunk 一张卡 |
| 错误 | 流里一条短错误，可重试；不要模态 |

一轮里用户句只出现一次（现在 `TurnSummaryCard` 顶部已经有 prompt，节点里又可能再画一遍——大修时只留一处）。

#### 计划

对标 Desktop 的 **Todo 清单：一张卡，原地打勾**。

现在的问题：

- `task-timeline-reducer.ts` 每来一个 `plan` 事件就 `nodes.push` 一张新卡
- `TurnSummaryCard` 画成 `Plan · 3 项`
- `App.vue` 又在右侧再画一份 `plan-list`

Desktop 不是这样。ACP 的 `session/update` `plan` 是整表快照，后来的事件是同一张清单的新状态，不是新计划。

锁死规则：

1. **每个 Turn 最多一张计划卡。** reducer 遇到后续 `plan` 只替换 `entries`，保留第一张卡的位置和 `nodeId`（建议 `taskId:turnId:plan`，不要带 sequence）。
2. **画成 checklist，不要写 `Plan`。**  
   - `pending`：空圈  
   - `in_progress`：当前步，细 spinner 或半圈  
   - `completed`：打勾，文案可弱一点  
   - `priority` 不做成彩灯；最多 high 一项更靠前，不要红黄绿标签墙
3. **进行中默认展开**（用户要看见下一步）；Turn 结束后默认折成「计划 · 3/3 完成」，点开仍能回看。
4. **不要**因为 ACP 暂时丢掉 `plan_update` 就在 UI 叠十张清单。GACP-01 若证实 Grok 会发 `plan_update`，再在 Adapter 里映射成「同一 plan 节点的补丁」，UI 不用变。
5. 右侧检查器不再放「执行计划」主副本。抽屉里若还要，只能是同一数据的只读缩略，点一下滚回对话里那张卡。

组件：`PlanChecklist.vue`，只吃 `AgentPlanEntry[]` + `active: boolean`。

#### 子 Agent

对标 Desktop 的嵌套任务卡，细则仍在 GACP-06，皮肤必须和上面计划卡、工具行是一家：

- 和计划卡同样的圆角、字号、边，不要更花
- 折叠态：名字 + 进行中/完成/失败 + 工具数
- 展开：内部只有 `ToolRow`，缩进 12px
- 不进侧栏，不另开 Task

没有父子协议字段时，不画空壳子 Agent，工具退回扁平行。

#### 三种块的主次

从上到下权重：

1. 用户句、助手回复（最大）
2. 进行中的计划当前步、进行中的子 Agent、待批权限
3. 已完成的工具行、已完成的计划/子 Agent（默认折）
4. 思考、usage（默认折，usage 没数据就藏）

---

### 6. 对话流里的工具（便捷的关键）

不要再渲染：

```text
Tool    读取 package.json · in_progress
```

改成一行：

```text
▸ 读了 package.json
```

进行中用细 spinner；完成后默认收起。同一类连续读取可合成「读了 8 个文件」。

计划：折叠成「计划 · 3 步」，展开才是条目。  
思考：默认折叠「思考过程」。  
权限：插在流里的一张小卡，主按钮「本任务允许」（GACP-03），不要模态罩全屏（破坏性操作除外）。

### 7. 子 Agent（本计划和 GACP-06 共用皮肤）

视觉必须和工具行是一套，只是多一层：

```text
┌─────────────────────────────────────────┐
│ ◉ 探查测试结构              进行中   ▾ │
│   已运行 3 个工具 · 点开查看             │
└─────────────────────────────────────────┘
```

展开后，孩子的读/写/命令用第 6 节同一套工具行，左侧多 12px 缩进。  
两个孩子上下叠，不要和父回复抢气泡。  
失败：卡片左边改危险色，标题旁写失败，不要把错误糊进父消息。

没有协议父子字段时，不画空壳「子 Agent」，工具仍用第 6 节扁平行。细则锁在 GACP-06。

### 8. 页眉只留一行

- 左：当前对话标题，双击可改（P0-10 已有重命名语义）。
- 右：停止（仅执行中）、打开检查器。
- 删掉状态芯片丛和「断开/连接 Grok」主按钮。
