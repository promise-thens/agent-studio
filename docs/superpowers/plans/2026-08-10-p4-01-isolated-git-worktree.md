# P4-01 隔离 Git Worktree 实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**优先级：** P4 / 权重 4（多脑并发的安全前提）

**目标：** 为并行 Runtime 任务创建、追踪、回收独立 Git worktree，避免多个 Agent 和用户修改同一工作目录。

**核心数据流：** 用户选择基准提交和项目；Worktree capability 校验仓库状态并创建受控目录/分支；任务快照绑定 worktree，完成后用户审阅并显式保留、合并或清理。

**约束与边界：** 不对用户原工作区执行 reset/stash/clean；不自动删除含未提交改动的 worktree；不默认合并或推送。

**主要风险：** 路径逃逸、分支冲突、磁盘占用和用户已有脏改动；限定工作根、记录 ownership、创建前检查、清理前二次确认。

**技术栈：** Electron 39、Vue 3、TypeScript、electron-vite、pnpm 10、Node.js 20+、Vitest；需要 Runtime 协议时以当期官方 schema 与本机实测为准。

## 实施范围

**前置依赖：**
- 依赖 P3-03、P0-08。

**文件范围：**
- 新增 `src/main/capability/git-worktree.ts`、测试；修改项目体检、任务快照和工作台 UI。

**安全策略：**
- 安全是与操作风险匹配的护栏：低风险只读操作可在任务范围授权；写入与命令需展示目标和影响；删除、外发数据、登录态、屏幕和剪贴板始终显式确认。
- Renderer 不接触密钥、任意 IPC、文件系统或子进程；所有跨进程数据须可序列化、限长并脱敏。
