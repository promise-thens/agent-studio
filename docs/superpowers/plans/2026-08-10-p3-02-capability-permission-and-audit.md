# P3-02 Capability 权限与本地审计 实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**优先级：** P3 / 权重 5（扩展高权限能力的护栏）

**目标：** 让 Capability Pack 的具体操作通过统一 Permission Broker，并提供可筛选、可删除的最小本地审计记录。

**核心数据流：** Capability Registry 以 capabilityId 标识操作来源；Broker 根据 Manifest 声明和用户授权决策；审计存储记录摘要、结果、时间和范围。

**约束与边界：** 审计记录不保存密钥、屏幕原图、剪贴板全文、完整网页响应或命令环境；不做云端监控或行为画像。

**主要风险：** 审计过少无法追溯，过多又成为敏感数据仓库；采用操作摘要、字段白名单、保留周期和用户可清除策略。

**技术栈：** Electron 39、Vue 3、TypeScript、electron-vite、pnpm 10、Node.js 20+、Vitest；需要 Runtime 协议时以当期官方 schema 与本机实测为准。

## 实施范围

**前置依赖：**
- 依赖 P0-08、P3-01。

**文件范围：**
- 新增 `src/main/capability/capability-executor.ts`、`src/main/security/audit-store.ts`、测试；修改 Broker 与设置审计页面。

**安全策略：**
- 安全是与操作风险匹配的护栏：低风险只读操作可在任务范围授权；写入与命令需展示目标和影响；删除、外发数据、登录态、屏幕和剪贴板始终显式确认。
- Renderer 不接触密钥、任意 IPC、文件系统或子进程；所有跨进程数据须可序列化、限长并脱敏。
