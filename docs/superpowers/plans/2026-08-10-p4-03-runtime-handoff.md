# P4-03 Runtime 接力 实施计划

> **致执行者：** 优先按任务顺序逐项落地，并在每个任务完成后做业务逻辑验证。步骤使用复选框 (`- [ ]`) 语法进行跟踪。

**优先级：** P4 / 权重 3（协作能力）

**目标：** 支持分析—实现、实现—审查与失败转交，让用户选择将受控、脱敏的任务上下文交给另一 Runtime。

**核心数据流：** 用户在任务上发起 handoff；系统生成可预览的 handoff package（目标、计划、摘要、Diff/验证引用、限制）；目标 Runtime 在新 task/worktree 接收并确认启动。

**约束与边界：** 不自动转交完整对话、密钥、屏幕、剪贴板、原始环境或无限工具输出；不在原任务运行中静默切换 Runtime。

**主要风险：** 上下文遗漏导致重复工作，或过度转交泄漏敏感内容；提供用户可编辑预览、字段白名单、大小上限和来源引用。

**技术栈：** Electron 39、Vue 3、TypeScript、electron-vite、pnpm 10、Node.js 20+、Vitest；需要 Runtime 协议时以当期官方 schema 与本机实测为准。

## 实施范围

**前置依赖：**
- 依赖 P2-04、P0-06、P0-07、P4-01。

**文件范围：**
- 新增 `src/main/agent/handoff-service.ts`、测试；新增 `HandoffReview.vue`；修改 history、workbench 与 worktree 能力。

**安全策略：**
- 安全是与操作风险匹配的护栏：低风险只读操作可在任务范围授权；写入与命令需展示目标和影响；删除、外发数据、登录态、屏幕和剪贴板始终显式确认。
- Renderer 不接触密钥、任意 IPC、文件系统或子进程；所有跨进程数据须可序列化、限长并脱敏。

## 验收标准

- [ ] 接力包可在发送前完整预览；目标 Runtime 不获得原任务的密钥或越权授权；原、目标任务的关系可在历史中追溯。
- [ ] 相关新增核心函数、IPC Handler、密钥/权限边界均有中文注释，且新增测试只使用假凭据和本地 Mock。
- [ ] 目标文件 ESLint、相关 Vitest、`pnpm typecheck`、`pnpm build` 与 `git diff --check` 在 Node.js 20+、pnpm 10.x 下完成；UI/Electron 改动另有对应开发版手工走查记录。
